Anchor

Anchor adds reactive behavior to standard HTML through a small set of attributes and elements. It requires no build step or compiler.

Overview

Anchor extends HTML with attributes and elements such as @id, <repeat>, <if>, and bind, and connects them to a reactive data store. Pages are written as ordinary HTML and enhanced by a single script.

A page remains valid HTML before the script loads. Developers familiar with HTML need only learn the attributes and elements documented in this reference.

Anchor must be served over http:// or https://. Opening a page directly from the file system (file://) is not supported. Use any local development server, for example npx serve.

Getting started

Include the script in the page and write HTML as usual. Anchor processes the document after it has finished parsing, so markup may appear before or after the script tag.

<script src="https://cdn.jsdelivr.net/gh/iamkave/Anchor@1.0.0/interpreter.js"></script>

<h3>Enter your name</h3>
<form @NameForm>
    <input @NameInput type="text">
    <input type="submit" value="Greet">
</form>

<format await="NameForm:submit">
    <p>Hello, <r value="@NameInput"></r>!</p>
</format>

This example collects a name from a form and displays a greeting when the form is submitted.

Applications that manage data or call functions use an inline <script> block that works with the global Anchor object, described in Reactivity.

Reactivity

Data is published with Anchor.expose. Anchor tracks changes to published data and updates every part of the page that depends on it.

Exposing data

let { GroceryList } = Anchor.expose({ GroceryList: [] });

GroceryList.push({ name: "Milk" }); // the page re-renders automatically

Anchor.expose() returns the reactive versions of the values it receives. Assign the returned values, as shown above, and modify those. Changes made to the original objects are not tracked.

Nested objects and arrays are reactive as well. For example, user.address.city = "Berlin" updates everything that depends on user, provided user was obtained from expose().

Reading and writing values

Use Anchor.get and Anchor.set to read and update exposed values from JavaScript.

CallDoes
Anchor.get(name)Returns the current value of an exposed root. Logs an error and returns undefined if name was not exposed.
Anchor.set(name, value)Replaces an exposed root's value and notifies watchers.
Anchor.set(name, prev => next)Updater form. Receives the current value and returns the new value.
Anchor.expose({ pageSize: 10 });

// safe even if called from two different click handlers in a row
Anchor.set("pageSize", n => n - 1);

Update behavior

Multiple changes to the same value within one synchronous block result in a single update.

Identifiers (@id)

Any element can be named by adding @Name as a bare attribute. Anchor removes the attribute, registers the element as Anchor.elements.Name, and sets id="Name" if the element does not already have an id.

<input @SearchBox type="text">

Directives refer to named elements by identifier, for example await="SearchBox:input" or params="@SearchBox".

Case sensitivity

Identifiers are case-sensitive: @GroceryName and @groceryname refer to different elements. This requires the page to be served over http:// or https://. When served from file://, identifiers are treated as lowercase.

<repeat>

Renders a block of markup for each entry of an array or object. The output updates whenever the source data changes.

<ul>
  <repeat as="item" in="$GroceryList">
    <li>[item.name]</li>
  </repeat>
</ul>

as names the loop variable and in references an exposed value. Inside the loop body, [item.name] is replaced with the value at that path. Interpolation works in text and in attribute values:

<repeat as="u" in="$Users">
    <p class="[u.role]" title="Hi, [u.name]">[u.name]</p>
</repeat>

A bracket expression is evaluated only when its first name is a loop variable. Other bracketed text, including the [$Foo] and [@Foo] reference forms used elsewhere, is left unchanged. To print a literal bracket, escape it with a backslash: \[not a lookup\].

Looping over an object

Provide two comma-separated names in as to receive the key and the value:

<repeat as="key, value" in="$Settings">
    <dt>[key]</dt><dd>[value]</dd>
</repeat>

The loop variable

Each iteration provides a loop object:

FieldMeaning
[loop.number]1-based position (1, 2, 3)
[loop.index]0-based position
[loop.first]true on the first item
[loop.last]true on the last item
[loop.length]total number of items

To use a named index variable instead, add the index attribute:

<repeat as="item" in="$Items" index="i">
    <li>#[i]: [item.name]</li>
</repeat>

Sorting (sort)

sort="name"ascending by item.name
sort="-price"descending by item.price
sort="name,-price"multiple keys; later keys break ties
sort="key" / sort="-key"when looping an object, sort by the property name itself rather than a field on the value

Values are compared numerically when both parse as numbers, and as locale-aware strings otherwise. Missing values sort last in either direction.

Paging (limit)

<repeat as="item" in="$Items" limit="$pageSize">...</repeat>

limit accepts a number or a reference, so a control can drive it reactively. A value below zero produces an empty list. A value that is not a number is logged as an error and the limit is ignored for that render.

Empty state

An <else> placed directly inside <repeat>, without a preceding <if>, is displayed when the resulting list is empty:

<repeat as="item" in="$Items">
    <li>[item.name]</li>
    <else><li class="empty">No items.</li></else>
</repeat>

An <else> that follows an <if> is the alternative for that condition. An unpaired <else> belongs to the loop.

<if> inside a loop

<if> can be used inside a loop body and can reference loop variables by name, without a $ or @ prefix:

<repeat as="u" in="$Users">
    <if test="u.role" eq="admin"><b>Admin</b></if>
    <else>Member</else>
    [u.name]
</repeat>

Inside a loop, the condition is evaluated once when each row is rendered, and the non-matching branch is removed from the DOM instead of being hidden.

Reactivity

A loop re-renders when its in source changes, and when any $ value referenced by an inner <if> changes.

Deferred rendering (await)

<repeat as="result" in="$Results" await="SearchForm:submit">...</repeat>

With await, the loop remains hidden and does not render until the named event has fired once. Without it, the loop renders immediately and stays reactive.

The <r> element

The <r value="..."> element inserts a value and can be used in place of bracket interpolation inside a loop body:

<repeat as="item" in="$Items">
    <li><r value="item.name"></r></li>
</repeat>

<if> / <else>

Shows or hides markup based on a condition. Outside a loop, the element is toggled with display: none and remains reactive.

<if test="$Age" gte="18">Adult</if>
<else>Minor</else>

test takes a reference ($, @, or []). An <else> applies only when it is the immediate next sibling of the <if>.

Comparators

AttributeMeaning
eq / neqequal / not equal
gt / gtegreater than / greater-or-equal
lt / lteless than / less-or-equal
hastrue unless the value is null, undefined, or an empty string. Takes no comparison value
notnegates the whole result (combine with any of the above, or with a bare test)

Without a comparator, <if test="$Cart"> checks truthiness. An array is true when it contains at least one item.

When both sides look like numbers they are compared numerically. Boolean values compare correctly against the literals eq="true" and eq="false".

Deferred evaluation (await)

<if test="@Age" gte="18" await="AgeForm:submit">Adult</if>
<else>Minor</else>

Both branches remain hidden until the named event has fired at least once.

<call>

Invokes a JavaScript function from markup, in response to an event, or immediately when the page is parsed if no await attribute is given.

<button @SaveBtn>Save</button>
<call fn="save" params="@NameInput" await="SaveBtn:click"></call>

Only functions registered with Anchor.exposeFunctions() can be called. Functions in global scope are not accessible.

function save(name) { /* ... */ }
Anchor.exposeFunctions({ save });

If fn names a function that has not been exposed, an error is logged to the console and no function is called.

Attributes

AttributeMeaning
fnrequired. The name of an exposed function
paramsoptional. A reference, or comma-separated list of references, passed to the function as arguments
awaitoptional. "Element:event". Without it, the call runs once when the page is parsed
returncaptures the function's return value and displays it in a <span> inserted right after the <call>
pendawaits the function itself (for an async function), before using its resolved value

Each call dispatches an invoke event when it runs. Other directives can listen for it with await="CallName:invoke", for example to update a block only after a specific action completes.

<format await="CallWeather:invoke">
    Temperature: <call @CallWeather fn="getTemperature" params="@City"
          await="CityForm:submit" return pend></call>
</format>

When return and pend are combined, the first call dispatches invoke twice: once when the result placeholder is created and again when the resolved value is available. Later calls dispatch it once. Handlers attached to invoke should tolerate the additional first event.

Two-way binding (bind)

Add bind="$path" to an <input>, <textarea>, or <select> to keep the control synchronized with an exposed value in both directions. User input updates the data, and changes to the data update the control.

Anchor.expose({ user: { name: "" } });
<input bind="$user.name">

Checkboxes bind through checked. A radio button is checked when its value equals the bound data. Other controls bind through value, synchronizing on the input event, or on change for checkboxes, radio buttons, and <select>.

The bind value must be a $ reference to an exposed value.

Form capture (pushto)

Whereas bind operates per field and in both directions, pushto collects an entire form into an object when the form is submitted. Add it to a <form>:

<form pushto="$profile">
    <input name="name">
    <input name="subscribed" type="checkbox">
    <input type="submit">
</form>

Fields without a name attribute are ignored. Checkboxes are collected as booleans. For radio buttons, only the checked option contributes a value. <select multiple> is collected as an array of the selected values. Submit, button, and reset inputs are excluded.

The target object is updated in place, so existing references to it remain valid.

<fetch>

Performs an HTTP request declaratively. @id and pushto are required. The @id lets other directives listen for the invoke and error events, and pushto names the exposed value that receives the response.

<fetch @Weather
       url="https://api.example.com/forecast?city=[@City]"
       pushto="$weather"
       await="CityForm:submit"></fetch>
AttributeMeaning
urlrequired. [@Field] and [$path] segments are resolved and URL-encoded automatically
pushtorequired. The exposed value that receives a successful response
methoddefaults to GET
bodya reference resolved and sent as the request body on non-GET requests (JSON-stringified automatically unless it's already a string)
parse"json" (default) or "text"
awaitwithout it, the request fires immediately on page load

Loading and error state

Anchor automatically exposes a loading value and an error value alongside the root named by pushto:

pushto="$weather"  ->  $weatherLoading (boolean), $weatherError (string | null)
<if test="$weatherLoading">Loading</if>
<if test="$weatherError" has>Unable to load weather.</if>

The response, the loading state, and the error state are stored independently. A failed request does not overwrite the last successful response, and the response is not cleared while a new request is in progress.

A response with an error status such as 404 or 500 is treated as a failure and dispatches error rather than invoke. If a new request starts before an earlier one completes, the earlier response is discarded.

<format>

Displays a block of markup when a named event fires, resolving any <r> elements inside it at that time. It is not otherwise reactive:

<format await="NameForm:submit">
    <p>Hello, <r value="@NameInput"></r>!</p>
</format>

The block is hidden with display: none until the event fires, and is evaluated again each time the event fires. It suits result blocks tied to a form's submit event or a call's invoke event.

<wraps> (components)

Defines reusable components. A template is declared once and can then be used as an HTML tag anywhere on the page. Definitions are placed in a single <wraps> block, conventionally in <head>, and are read at startup. Usages can be added at any time, but new component types must be declared before the initial page load completes.

<wraps>
  <wrap tag="bubble">
    <if test="{get.sender}" eq="left">
      <div class="bubble left">{get.text}</div>
    </if>
    <else>
      <div class="bubble right">{get.text}</div>
    </else>
  </wrap>
</wraps>

<bubble sender="right" text="hi!"></bubble>

Each attribute on a usage is available inside the template as {get.attrName}. {get.content} resolves to the inner HTML of the usage instead of an attribute.

Special characters (&, <, >) in a usage's inner content may be escaped twice when inserted into a plain-text slot. For dynamic content that may contain these characters, pass it as an attribute such as {get.text} instead.

Namespaced identifiers

An attribute name beginning with : in a template becomes an @id prefixed with the usage's own identifier. Each usage therefore receives its own uniquely named elements:

<wrap tag="search">
    <input :Field placeholder="{get.placeholder}">
    <button :Btn>{get.label}</button>
</wrap>

<search @SearchBar placeholder="Type to search" label="Go"></search>

In this example the input is registered as @SearchBarField and the button as @SearchBarBtn. A usage may omit its @id only if its template contains no : placeholders; otherwise an error is thrown.

References such as params=":Field" or value=":Btn" elsewhere in the template are rewritten in the same way, so a <call params=":Field"> inside the template refers to that usage's own field.

Creating components in JavaScript

A component usage can also be created in JavaScript and inserted with Anchor.mount():

const bubble = Anchor.createWrap("bubble", null, "", { sender: "left", text: "hello" });
Anchor.mount(bubble, "@ChatLog", "append");

The element returned by createWrap is expanded when it is inserted into the document.

JavaScript API reference

This section describes the JavaScript interface available to scripts on the page.

Anchor.ready

A promise that resolves when Anchor has finished initializing.

Use Anchor.ready rather than DOMContentLoaded before calling Anchor.mount, Anchor.createWrap, or Anchor.loop. These functions are not guaranteed to be available when DOMContentLoaded handlers run. Anchor.ready can be used at any point after the script loads.

Anchor.ready.then(() => {
    Anchor.mount(Anchor.loop(GroceryList, item => `<li>${item.name}</li>`, true), "@List");
});

Anchor.expose(vars)

Publishes data as reactive state and returns the reactive versions of the values provided. See Reactivity.

Anchor.get(name) / Anchor.set(name, value)

Reads or replaces an exposed value from JavaScript. set also accepts an updater function, prev => next. See Reactivity.

Anchor.exposeFunctions(fns)

Registers the functions that <call> is permitted to invoke. See <call>.

Anchor.elements

An object that maps each registered @id to its element, for example Anchor.elements.SearchBox.

Anchor.mount(el, target, position)

Inserts an element into the document. target may be an Element, an "@id" string, or a CSS selector. position defaults to "append":

appendlast child of the target
prependfirst child of the target
beforeimmediately before the target
afterimmediately after the target
replacereplaces the target outright

Mounted content is processed like any other markup: identifiers are registered, <call> elements are activated, and component usages are expanded.

Anchor.createWrap(tagName, id, innerHTML, attrs)

Creates a component usage element in JavaScript. See <wraps>.

Anchor.loop(source, render, reactive)

A JavaScript alternative to <repeat> that builds a list from a template function. Returns a container element to pass to Anchor.mount:

let { GroceryList } = Anchor.expose({ GroceryList: [] });

Anchor.mount(
    Anchor.loop(GroceryList, item => `<li>${item.name}</li>`, true),
    "@List"
);

render(value, key) returns an HTML string for each entry, where key is the array index or the object property name. Anchor markup syntax is not processed inside the string, and the output is not escaped. Escape any untrusted text before including it.

The third argument controls reactivity:

  • reactive = false (default): source is read once and the container does not change afterward. Call Anchor.loop again to reflect later changes.
  • reactive = true: source must be a value returned directly by Anchor.expose(). The container is updated in place whenever that value changes. Nested values such as user.addresses cannot be tracked; in that case the list is rendered once and a message is logged.

Security

This section describes how Anchor handles data and where validation is the developer's responsibility.

Interpolated text

Values interpolated with [item.name] in text content and in most attribute values are set with textContent or setAttribute, never innerHTML. Markup in the data is displayed as literal text and is not parsed. Access to __proto__, constructor, and prototype is blocked for both reading and writing, and an error is logged.

URL attributes (href, src) and event-handler attributes (onclick and similar) are not sanitized. Interpolating untrusted data into them can produce a javascript: URL or an active inline handler. Do not bind these attributes to data that is not fully trusted.

<call> allowlist

Only functions registered with Anchor.exposeFunctions() can be invoked by name through a fn attribute. See <call>.

Anchor.loop output

Unlike bracket interpolation, the string returned by an Anchor.loop render function is assigned with innerHTML. Escape any user-provided text before including it.
